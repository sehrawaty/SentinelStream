## Notes

- **P1**: Without index #10 the planner did not fall back to a full COLLSCAN -- it found index #8 ({severity,ts}) still applicable and used that instead, adding a FETCH-stage filter on status. #10 removes that extra filter by embedding status directly in the index seek. At this data volume (a handful of HIGH alerts) the docsExamined delta is small; the meaningful evidence is the winning plan's index name changing from the 2-field fallback to the exact 3-field match -- at larger HIGH-severity volumes the avoided FETCH-filter would show as a real docsExamined gap too.
- **P3**: Pipeline A's own $match filters on ts, not this compound -- this probe isolates index #4 directly rather than explaining the full aggregation, which would otherwise mix in ts-range plan noise unrelated to what #4 serves.

## Redis — the index-equivalent argument (no separate index structure)

`card:{c}:txns` as a **ZSet** gives an O(log N) skiplist-ordered window with
O(1) `ZCARD` -- a List would need an O(N) scan to count entries inside a time
bound and could not be trimmed by score at all. `GEOADD` maintains a
geohash-scored sorted set, making `GEODIST` O(1). The data structure choice
*is* the index here.

## Neo4j — deferred to Slice 12

The four uniqueness constraints (CLAUDE.md §4.4) each create a backing range
index, making `RING_FOR_CARD`'s seed lookup (`MATCH (seed:Card {cardId:
$x})`) an index seek rather than a label scan. Captured with `PROFILE`
once the ring query exists: `NodeByLabelScan` -> `NodeUniqueIndexSeek`,
recording the `db hits` delta -- the Neo4j counterpart to COLLSCAN -> IXSCAN.
